ECC · Everything Claude Code — ściągawka

Co wpisać, żeby coś się stało

Wybrane komendy i skille ECC pod Twój stack (React / Next.js / TypeScript / Python / ML). Ułożone tak, jak pracujesz — od pomysłu do commita. Przy każdej pozycji masz oznaczenie, jak się zachować.

/ KOMENDA

Wpisujesz sam, np. /ecc:plan "...". Świadoma akcja.

◆ SKILL

Mówisz nazwę („użyj tdd-workflow") albo Luna odpala auto, gdy pasuje kontekst.

🤖 HOOK

Nic nie robisz — dzieje się samo w tle (format, testy, nauka).

★ Najważniejsze — używaj tego świadomie

Continuous Learning v2 — pamięć, która uczy się Twojego stylu

Hook obserwuje Twoją pracę w tle i zapisuje „instynkty" — krótkie lekcje z oceną pewności (confidence). Na starcie każdej sesji wstrzykuje najlepsze (domyślnie max 6, tylko confidence ≥ 0.7). Zbieranie jest automatyczne — wartość dają dopiero Twoje świadome ruchy poniżej.

OBSERWUJE 🤖→ INSTYNKT→ /promote→ /evolve→ SKILL ◆
1 Pracuj normalnie. Hook łapie wzorce sam — nic nie robisz. 🤖 auto
2 Koniec dobrej sesji → /ecc:learn-eval — świadomie zapisujesz, co zadziałało. Robi samoocenę jakości i sam wybiera: projekt czy global.
3 Co jakiś czas → /ecc:instinct-status — widzisz, czego się nauczył i z jaką pewnością. Instynkt „łapie" dopiero od ≥ 0.7: powtarzalne zachowanie podbija próg, jednorazowe ginie. Klucz: bądź konsekwentny.
4 /ecc:promote — dobry instynkt z jednego projektu podnieś do globalnego, żeby działał we wszystkich repo.
5 Uzbierało się dużo powiązanych → /ecc:evolve — klastruje je w prawdziwy, wielokrotnego użytku skill.
6 Higiena → /ecc:prune · /ecc:instinct-export — kasuje stare nieużyte (>30 dni) / backup i współdzielenie między maszynami.

Model myślowy: instynkt = krótka lekcja z pewnością · skill = utrwalona wiedza. System zbiera sam — Ty świadomie promujesz dobre i evolvujesz je w skille. Bez kroków 2–5 zostaje przy słabych, nieużywanych instynktach.

Agenci (subagenci)

bez komendy — mówisz, co ma zrobić
Agent tool (mój, nie Twój) 🤖 AUTO

Nie ma komendy do odpalania agenta. Ja decyduję, kiedy sięgnąć po subagenta — np. code-reviewer po napisaniu kodu, security-reviewer przed commitem, tdd-guide przy nowej funkcji/bugu.

Kiedy: zawsze w tle, wg reguł z agents.md. Nie musisz nic pisać.

„użyj agenta X" / „puść X na to" ◆ WYWOŁANIE

Chcesz konkretnego agenta teraz — po prostu powiedz nazwę. Nie musisz znać dokładnej nazwy, opisz co potrzebujesz.

Przykład: „użyj agenta planner do rozplanowania eksportu wyceny do PDF w SteelQuote" · „puść security-reviewera na endpoint logowania w SafetyHub"

Równolegle ◆ WYWOŁANIE

Niezależne sprawdzenia mogą lecieć jednocześnie, zamiast po kolei — szybciej dostajesz komplet wyników.

Przykład: „sprawdź to równolegle: security-reviewer, performance-optimizer i react-reviewer"

planner · architect · code-explorer · code-architect ◆ AGENT

Przed kodem: planner robi plan, architect podejmuje decyzje projektowe, code-explorer/code-architect mapują istniejący kod pod nową funkcję.

Przykład: „użyj code-explorer żeby zrozumieć jak liczona jest wycena w SteelQuote zanim dodamy nowy typ stali"

e2e-runner · doc-updater · refactor-cleaner ◆ AGENT

Po kodzie: e2e-runner testuje krytyczne ścieżki użytkownika, doc-updater aktualizuje dokumentację/codemapy, refactor-cleaner sprząta martwy kod.

Przykład: „e2e-runner: przetestuj cały flow wyceny od formularza do PDF-a"

Start nowej funkcji

pomysł → plan
/ecc:plan "Dodaj logowanie OAuth" / KOMENDA

Planner przekształca wymagania w blueprint krok-po-kroku i czeka na Twój CONFIRM zanim ruszy kod.

Kiedy: zawsze na start większej roboty. Nie pisze kodu bez Twojej zgody.

Przykład: /ecc:plan "Dodaj grywalizowane odznaki za ukończone szkolenia BHP w SafetyHub"

/ecc:plan-prd · /ecc:prp-prd / KOMENDA

Najpierw lekki, problem-first PRD (co i po co), potem przekazuje do planowania.

Kiedy: nowy produkt/moduł, gdzie warto najpierw dopiąć „dlaczego".

/ecc:orch-add-feature "..." / KOMENDA

Pełny pipeline end-to-end: research → plan → TDD → review → commit za bramką.

Kiedy: duża funkcja, którą chcesz „od zera do commita" jednym ruchem.

Przykład: /ecc:orch-add-feature "eksport wyceny stali do PDF z logo firmy"

Pisanie kodu (TDD)

testy first → implementacja
/ecc:react-test / KOMENDA

Wymusza TDD dla Reacta: testy React Testing Library (behavior + a11y) najpierw, potem komponent. Wykrywa Vitest/Jest.

Kiedy: nowy komponent/hook w React/Next.

Przykład: /ecc:react-test na komponencie formularza wyceny w SteelQuote — najpierw testy walidacji pól, potem implementacja.

tdd-workflow · python-testing ◆ SKILL

TDD ogólne / dla Pythona: write-tests-first, cel 80%+ pokrycia.

Kiedy: backend/ML w Pythonie albo logika bez frameworka.

Przykład: „napisz funkcję liczącą cenę stali wg wagi i typu, TDD" — dostaniesz test przed implementacją.

react-patterns · frontend-patterns · fastapi-patterns · pytorch-patterns ◆ SKILL

Gotowe wzorce architektoniczne dla danego stacka — zaciągane jako kontekst.

Kiedy: chcesz, żeby kod trzymał się konwencji frameworka.

Build się sypie

błędy kompilacji / typów
/ecc:react-build / KOMENDA

Naprawia błędy buildu React/Next (Vite, webpack, esbuild): JSX/TSX, hydration mismatch, granice server/client, brakujące typy. Minimalne, chirurgiczne zmiany.

Kiedy: npm run build / dev sypie błędami frontendu.

Przykład: deploy SteelQuote przez DeepAgent nie startuje po podmianie plików — /ecc:react-build zamiast ręcznego grzebania w stack trace.

/ecc:build-fix / KOMENDA

Uniwersalny: wykrywa system build i przyrostowo naprawia błędy typów/kompilacji.

Kiedy: nie-Reactowy projekt albo mieszany build.

Review przed commitem

jakość · bezpieczeństwo
/ecc:code-review / KOMENDA

Review lokalnych niescommitowanych zmian albo PR-a (podaj numer/URL).

Kiedy: zanim zrobisz commit / otworzysz PR.

Przykład: /ecc:code-review po zmianach w liczeniu wyceny, zanim wyślesz do DeepAgent na hosting.

/ecc:security-scan / KOMENDA

AgentShield skanuje sekrety, hooki, MCP, uprawnienia, powierzchnie ataku agenta.

Kiedy: przed publikacją / gdy dodajesz nowe MCP lub klucze.

Przykład: przed wdrożeniem SafetyHub — sprawdza, czy dane BHP użytkowników są bezpiecznie obsłużone.

/ecc:test-coverage / KOMENDA

Analizuje pokrycie, wskazuje luki i dogenerowuje brakujące testy do progu.

Kiedy: coverage spadło albo dopinasz moduł.

Bug fix i refactor

bezpieczne zmiany
/ecc:orch-fix-defect "..." / KOMENDA

Repro buga jako failing test → fix do zielonego → review → commit za bramką.

Kiedy: masz konkretny bug i chcesz go domknąć porządnie.

Przykład: /ecc:orch-fix-defect "wycena liczy złą cenę przy stali nierdzewnej"

/ecc:orch-refine-code / KOMENDA

Refactor zachowujący zachowanie: testy zielone → przebudowa → dalej zielone → review.

Kiedy: sprzątasz kod bez zmiany działania.

/ecc:refactor-clean / KOMENDA

Wykrywa i usuwa martwy kod, z weryfikacją po każdej zmianie.

Kiedy: czyszczenie nieużywanego kodu.

Design (Twój lane)

jedna główna skilla, na AUTO
ui-ux-pro-max + design-motion-principles (motion) ◆ SKILL

Jedyna główna design-skilla na auto-routingu w CLAUDE.md — przy UI/landing/komponencie Luna sięga po nią sama, bez pisania „użyj skilla". Przy animacji/motion dokłada design-motion-principles.

Kiedy: cokolwiek wizualnego. Świadomy wybór z 2026-07-08: jedna ostra skilla > kilka nakładających się (rozmywają się nawzajem).

Przykład: „przeprojektuj kartę wyniku wyceny w SteelQuote, ma wyglądać bardziej premium" — odpali się sama, nie musisz nic pisać.

impeccable · frontend-design + taste-cluster ◆ SKILL

Zainstalowane, ale nie na auto — celowo w tle, żeby nie dublować ui-ux-pro-max. Odpalisz je tylko jawnie po nazwie.

Kiedy: chcesz konkretnie drugą opinię/inny styl niż ui-ux-pro-max daje domyślnie.

„bez designu" / „plain" / „szybki hack" 🤖 OPT-OUT

Powiedz to wprost, a Luna pomija auto-routing designu i robi zwykłą, minimalną zmianę bez pełnego przejścia designerskiego.

Kiedy: szybka poprawka, prototyp, nie chcesz narzutu design-skilli.

/ecc:gan-design / KOMENDA

Pętla generator/ewaluator dla frontendu — iteruje warianty i ocenia je punktowo.

Kiedy: chcesz kilka wariantów UI i wybór najlepszego.

Jak się zachować — 4 zasady

  1. / KOMENDA — piszesz sam, np. /ecc:plan "...". To Twoja świadoma decyzja „zrób to teraz".
  2. ◆ SKILL — powiesz nazwę („użyj tdd-workflow") albo Luna odpali go automatycznie, gdy zadanie pasuje. Design-skille masz już na auto.
  3. 🤖 HOOK — nie robisz nic. Sam się odpala: auto-format po edycji, TS-check, ostrzeżenie o console.log, nauka instynktów, podsumowanie sesji.
  4. Skala zadania — duże/end-to-end → orch-*. Pojedynczy krok → jedna komenda (np. /ecc:react-build). W wątpliwości: zacznij od /ecc:plan.
